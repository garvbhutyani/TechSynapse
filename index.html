Development

Software that stays correct as it grows. We study how frontends, APIs and delivery pipelines are designed, then build them with tests and deployment in mind from the first commit.

Frontend

Interfaces people can use

  • Semantic HTML first, then styling and scripting
  • Keep component state as close as possible to where it is used
  • Body text needs at least 4.5:1 contrast (WCAG 2.2 AA)

Backend and APIs

Contracts that hold

  • Resource-oriented REST routes; PUT and DELETE are idempotent
  • Cursor-based pagination stays stable when data changes
  • GraphQL trades flexible queries for harder caching and cost control
  • Rate limits and timeouts protect every upstream dependency

Delivery

Ship without fear

  • Multi-stage Docker builds keep runtime images small
  • Pipeline order: lint, unit tests, build, integration tests, deploy
  • Health checks and a tested rollback before every release

Discipline 02

Data and databases

Data outlives every application that touches it. Model it carefully, index it for the queries you actually run, and keep transactions honest.

Tune a real query

CREATE INDEX idx_orders_user_created
  ON orders (user_id, created_at);

EXPLAIN ANALYZE
SELECT * FROM orders
WHERE user_id = 42
ORDER BY created_at DESC
LIMIT 10;

The composite index serves the filter and the sort together, so the database reads ten rows instead of the whole table.

Five drawers of theory

Modeling

1NF: atomic values and no repeating groups. 2NF: every non-key column depends on the whole key. 3NF: no non-key column depends on another non-key column.

Indexing

A B-tree turns a full scan into a logarithmic search. Column order matters: an index on (user_id, created_at) helps filters on user_id, but not on created_at alone. Every index slows writes and uses storage.

Transactions

ACID means atomicity, consistency, isolation and durability. Read committed prevents dirty reads; serializable also prevents phantom reads, at a throughput cost.

Query plans

Run EXPLAIN ANALYZE before tuning. Watch for sequential scans on large tables, row estimates far from actual counts, and sorts that spill to disk.

NoSQL and pipelines

Document stores suit evolving schemas; key-value stores suit caches and sessions. ETL transforms before loading; ELT loads raw data first and transforms inside the warehouse. Add quality checks at every stage.

Discipline 03

Security by design

Security is a property of the whole system, decided at design time. We model threats first, apply proven cryptography, and check every release against the common web risks.

Hover to turn the dial. Good security is boring, repeatable and checked.

Web risks

Risks you will meet first

  • Broken access control: check authorization on every request, on the server
  • Cryptographic failures: encrypt data in transit with TLS and never invent your own cipher
  • Injection: use parameterized queries and never concatenate user input into SQL
  • Authentication failures: require MFA, rate-limit logins and hash passwords with Argon2id or bcrypt

Symmetric

One shared key

AES-256 in GCM mode encrypts and authenticates data. Never reuse a nonce with the same key.

Asymmetric

Public and private

RSA and elliptic-curve keys sign messages and exchange keys. Public keys verify; private keys never leave the server.

Hashing

One way only

Hashes cannot be reversed. Store passwords with Argon2id or bcrypt, each with a unique salt, never with reversible encryption.

TLS 1.3

The handshake

  • ClientHello: the client offers cipher suites and a key share
  • ServerHello: the server picks parameters and sends its certificate
  • Both sides derive session keys and exchange Finished messages
  • Encrypted data flows; a full handshake takes one round trip

Process

Secure delivery

  • Threat model during design, not after launch
  • Scan dependencies and code in CI on every merge
  • Keep secrets out of repositories and rotate them
  • Review every production incident for root cause

STRIDE threat modeling

Spoofing

Prove identity with strong authentication.

Tampering

Sign messages and verify integrity.

Repudiation

Keep tamper-evident audit logs.

Disclosure

Encrypt data and expose the minimum.

Denial of service

Rate-limit, time out and shed load.

Elevation

Apply least privilege everywhere.

Validate first

Before you write code

  • Run 20 problem interviews and listen more than you pitch
  • Test demand with a landing page and a waitlist
  • Scope an MVP to one core job the user would pay to solve
  • Track activation and week-four retention, not just sign-ups

Unit economics

Does the math work?

Lifetime value is roughly ARPU times gross margin divided by churn rate. Compare it with customer acquisition cost.

Payback period = CAC ÷ (ARPU × gross margin)

Pitch

Six slides, one story

  • The problem, with evidence from interviews
  • Your solution and why it is different
  • Market size, bottom-up rather than guessed
  • Traction, the team, and the specific ask
